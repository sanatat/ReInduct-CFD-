# ReInduct-CFD Pro v3 — راهنمای فارسی

## ایده پژوهشی

نمونه‌کار چندفیزیکی برای نزدیک شدن به پروژه TU-BRIDGE مربوط به بازیافت حرارتی و واکنشی مواد باتری. این نسخه، **کدهای اجرایی و آزمون‌های عددی** دارد، نه صرفاً پروپوزال. این پروژه هنوز یک مدل صنعتی اعتبارسنجی‌شده نیست.

### معماری پروژه

1. `cfd/mac_channel.py`: حل دو‌بعدی معادلات ناویر–استوکس تراکم‌ناپذیر با شبکه staggered و روش تصحیح فشار. شرایط مرزی دوره‌ای در راستای طول و دیواره بدون لغزش در ارتفاع. یک ناحیه با مقاومت Brinkman هم قابل تعریف است.
2. `reactor2d/reactor.py`: حل پایسته انتقال گونه H₂/H₂O، تبدیل جامد NiO، انرژی گاز و جامد با دماهای مستقل، هدایت، تبادل حرارت و تابش. سرعت محاسبه‌شده از مرحله ۱ وارد این مدل می‌شود.
3. `em/variable_induction.py`: حل میدان مغناطیسی هارمونیک در صفحه رسانا، محاسبه جریان القایی و گرمایش ژولی، همراه تغییر رسانندگی با دمای میانگین جامد.
4. `cfd/mac_channel.py --B`: آزمایش مستقل Hartmann برای اثر میدان مغناطیسی بر سیال رسانا. **این همان کوپل کامل میدان مغناطیسی به راکتور گازی نیست.**
5. `plasma/radical0d.py`: مدل صفر‌بعدی بقای اتم‌ها برای تشکیل و بازترکیب رادیکال‌های هیدروژن. تخلیه الکتریکی واقعی یا توزیع انرژی الکترون‌ها شبیه‌سازی نشده است.
6. `multiregion/conjugate1d.py`: انتقال حرارت هدایتی بین دو ناحیه با مش مستقل، رسانندگی‌های متفاوت و شار سطح مشترک برابر و مخالف؛ یک بنچمارک یک‌بعدی و مستقل.
7. `src/reactor1d.cpp`: مدل ساده‌تر C++17 نسخه قبل با کنترل موازنه جرم.
8. `openfoam`: کیس پایه و کیس انتقال اسکالر غیرفعال؛ **هنوز در OpenFOAM اجرا نشده‌اند** و واکنش‌دار/چندناحیه‌ای کامل نیستند.

## پیش‌نیازها

در Linux Mint یا Ubuntu:

```bash
sudo apt update
sudo apt install g++ make python3 python3-pip python3-venv
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

### اجرای تمام آزمون‌های قابل‌تکرار

```bash
make all test emtest v3test
make v3study
make v3radicals
make v3multiregion
make v3doe
```

خروجی‌ها داخل `results/v3/evidence/` هستند. خروجی غربالگری فرایند در `results/v3/DOE/` است. نمودارهای دوبعدیِ میدان سرعت، دما و تبدیل، مطالعه شبکه و حساسیت به شدت میدان القایی تولید می‌شوند.

برای اجرای یک کیس جریان‌–واکنش–مغناطیس با کوپل یک‌طرفه جریان:

```bash
python cfd/mac_channel.py --end 7 --drag 0.7 --out results/v3/flow
python reactor2d/reactor.py --flow-file results/v3/flow/velocity.npz --out results/v3/reactor
```

**توجه:** `drag` در مدل جریان یک ضریب مقاومت Brinkman فرضی است؛ افت فشار Ergun در مدل راکتور فعلاً تنها یک شاخص پس‌پردازشی است و مستقیماً به معادله مومنتوم اعمال نشده.

## پوشش هفت مهارت موردنیاز

| مهارت | سطح شواهد اکنون | بخش باقی‌مانده |
|---|---|---|
| CFD واکنشی | دو‌بعدی: حل واقعی ناویر–استوکس و سپس حل واکنش روی میدان سرعت حاصل | کوپل کاملاً هم‌زمان مومنتوم و شیمی با خواص وابسته به تبدیل |
| چندفازی/چندناحیه‌ای | گاز و جامد با دو دمای مستقل در شبکه مشترک (LTNE) | مش جداگانه هدایتی در بنچمارک مستقل اجرا شده؛ انتقال بین‌فازی کامل در راکتور و دینامیک ذرات باقی است |
| دمای بالا / القایی | ژول و تابش و دماهای چندصد درجه‌ای | کویل واقعی و مواد دمای بالای اندازه‌گیری‌شده |
| الکترومغناطیس/MHD | MQS حل‌شده و Hartmann benchmark تست‌شده | حل میدان و نیرو در هندسه راکتور، مدل پلاسمای واقعی |
| C++ | کد واقعی C++17 و آزمون موازنه | نوشتن solver اختصاصی چندفیزیکی OpenFOAM با C++ |
| OpenFOAM | کیس‌های نمونه آماده اما اجرا نشده | نصب/اجرای نسخه سازگار و پورت شیمی–انرژی |
| ترمودینامیک/سینتیک | روابط آرنیوس، ΔG/K، موازنه و آزمون خاموش‌شدن واکنش | داده واقعی، برازش، تخمین عدم‌قطعیت |

**رزومه:** پس از اینکه شخصاً اجرای برنامه و خروجی‌ها را تأیید کردی، می‌توان گفت یک benchmark دوبعدی پایسته برای مدل‌سازی واکنشی با جریان محاسبه‌شده و گرمایش القایی ساخته‌ای. ادعای اجرای OpenFOAM، مدل کامل پلاسما، اعتبارسنجی آزمایشگاهی و Digital Twin صنعتی مجاز نیست.
